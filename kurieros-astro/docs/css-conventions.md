# CSS conventions

## Глобальные стили — только по классам

В `src/styles/*.css` запрещены селекторы по голому HTML-тегу для
семантических элементов. Конкретно нельзя:

```css
header { ... }
main { ... }
section { ... }
article { ... }
aside { ... }
nav { ... }
footer { ... }
```

**Почему.** HTML5 поощряет переиспользовать эти теги в разных
контекстах (`<header>` для сайтовой шапки, для шапки статьи, для
шапки секции; `<section>` для группировок любого уровня; и т.д.).
Глобальный селектор по голому тегу матчит все вхождения в проекте и
протекает в неожиданные места — например, стили сайтовой шапки
(`position: sticky`, `backdrop-filter`, `display: flex`) утекали на
`<header class="guide-hero">` в инфо-гайдах и страницах `/guide/*`,
ломая верстку на мобильных. См. `CSS-1` в `docs/backlog.md`.

**Как правильно.** Тегу — дискриминирующий класс, селектору — этот
класс:

```css
header.site-header { ... }     /* сайтовая шапка */
article.blog-post { ... }      /* пост блога */
section.feature-row { ... }    /* строка фич */
```

Внутри `.astro`-компонентов scoped CSS можно писать как угодно —
Astro автоматически добавляет уникальный data-атрибут, и утечки
физически невозможны.

## Когда добавляешь новый семантический тег

Если в шаблон/компонент попадает новый `<header>`, `<main>`,
`<section>`, `<article>`, `<aside>` или `<nav>` — **сразу** дай ему
дискриминирующий класс, даже если стилей под него пока нет. Иначе
случайно подхватит чужие глобальные правила при следующей правке CSS.

## Проверка перед PR

Чек-лист в `.github/pull_request_template.md` содержит соответствующие
галочки. Машинной проверки (stylelint) пока нет — она запланирована
в `CSS-1` (`docs/backlog.md`).
