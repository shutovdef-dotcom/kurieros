# Структура данных для генерации вакансий

Этот файл описывает данные, которые нужно прислать для генерации одной базовой вакансии и множества локальных вакансий по городам и транспорту.

Одна базовая вакансия хранится как `VacancySource`. Из нее генератор создает отдельные вакансии под каждую активную комбинацию:

```text
город + транспорт = отдельный offer = отдельная страница вакансии
```

## 1. Минимальный пакет данных

Для генерации вакансии нужно прислать:

1. Название вакансии.
2. Компания и логотип.
3. Реферальная ссылка для кнопки отклика.
4. Описание вакансии, требования, бенефиты и требуемые документы.
5. Переводы описания на все языки сайта.
6. Таблица зарплат по каждому городу и транспорту.
7. Таблица найма по городам: возраст, гражданство, медкнижка, формат оформления.
8. Источник данных: ссылка на таблицу, лендинг, кабинет партнера или другой источник.
9. Дата обновления условий.

## 2. Поддерживаемые языки

Контент вакансии должен быть подготовлен на всех языках сайта:

```text
ru, uz, tg, ky, hy, kk, az, uk, be, hi, vi, zh
```

Если переводов пока нет, можно прислать только `ru` и явно написать: `переводы нужно подготовить`. Для публикации лучше заполнить все языки.

## 3. Базовая информация

```yaml
vacancy:
  title: "Курьер Яндекс Еды"
  slug: "yandex-eda-courier"
  company:
    name: "Яндекс Еда"
    logo: "/logos/yandex-eda.svg"
  referralLink: "https://example.com/apply"
  isHot: true
  extraTags:
    - "food_delivery"
    - "flexible"
```

Поля:

| Поле | Обязательное | Что передавать |
| --- | --- | --- |
| `title` | да | Базовое название вакансии |
| `slug` | желательно | Латиницей, без пробелов |
| `company.name` | да | Название компании |
| `company.logo` | да | URL или локальный путь к логотипу |
| `referralLink` | да | Ссылка для кнопки "Откликнуться" |
| `isHot` | нет | `true`, если вакансию нужно выделять |
| `extraTags` | нет | Дополнительные технические теги |

## 4. Контент вакансии

Контент передаётся плоским объектом на русском языке (см. тип
`VacancyContent` в `src/data/vacancyTypes.ts`). Переводы НЕ передаются в
этом формате — добавляются отдельно через `i18n:extract` пайплайн (см.
`docs/i18n-translation-skill.md`).

```yaml
content:
  title: "Курьер Яндекс Еды в {city}"
  shortDescription: "Доставка заказов рядом с домом, свободный график и регулярные выплаты."
  description: |
    Яндекс Еда набирает курьеров в {city}. Можно доставлять заказы пешком,
    на велосипеде или на автомобиле. Район и график подбираются под кандидата.
  requirements:
    - "Смартфон на Android или iOS"
    - "Аккуратность и готовность доставлять заказы вовремя"
  benefits:
    - "Свободный график"
    - "Можно выбирать удобный район"
    - "Регулярные выплаты"
  requiredDocuments:
    - "Паспорт"
    - "СНИЛС"
    - "ИНН"
    - "Медицинская книжка, если требуется по условиям города"
  labels:
    - "Свободный график"
    - "Без опыта"
  searchTags:
    - "Яндекс Еда"
    - "курьер"
    - "доставка"
```

Важно:

- Поддерживаются **два плейсхолдера** (резолвятся в `jobs.ts:interpolate()`):
  - `{city}` — имя города как есть («Москва»).
  - `{cityPrep}` — предложный падеж («в Москве», «в Санкт-Петербурге»).
    Для городов вне `CITY_DATASET` — дефолт «в `<Город>`».
- Оба работают в `title`, `shortDescription`, `description`, `requirements[]`,
  `benefits[]`, `requiredDocuments[]`.
- `{cityPrep}` всегда резолвится в русский падеж — даже на не-RU
  страницах. Это потому что title/labels/searchTags на сайте всегда
  русские (policy), а реальные переводы описаний используют плейсхолдер
  `{city}` (без падежа). См. правила переводов в `add-vacancies-dialog.md`.
- `requiredDocuments` — базовый список документов для вакансии.
- Если для конкретного транспорта нужны дополнительные документы, они
  добавляются на уровне `offer.requiredDocumentsOverride`.

## 5. Транспорт

Поддерживаемые значения (`TransportMode` в `src/data/vacancyTypes.ts`):

| Код | Значение |
| --- | --- |
| `foot` | Пеший курьер |
| `bicycle` | Велокурьер, самокат |
| `auto` | Автокурьер |
| `remote` | Удалённая работа без выхода на маршрут (оператор поддержки, диспетчер) |

Дополнительно — `transportProvision` (`'own' | 'company' | 'not_required'`),
кто предоставляет транспорт. По умолчанию в `jobs.ts`:

| Транспорт | Default `transportProvision` |
| --- | --- |
| `foot`, `remote` | `not_required` |
| `bicycle`, `auto` | `own` |

Указывай явно, только если логика отличается от дефолта (например, велосипед
выдаёт компания → `company`).

## 8. Override-данные для города и транспорта

Если конкретная комбинация города и транспорта отличается от базового описания, добавь отдельную таблицу override:

| city | transport | ageFrom | medicalBook | employmentFormats | requirementsOverride | benefitsOverride | requiredDocumentsOverride |
| --- | --- | ---: | --- | --- | --- | --- | --- |
| Москва | auto | 18 | required | self_employed, gph | Права категории B; Стаж вождения от 1 года | Больше заказов на дальние расстояния | Водительское удостоверение; СТС автомобиля |
| Москва | bicycle | 16 | compensated | self_employed | Свой велосипед или самокат | Быстрое подключение | Документ на велосипед не нужен |

Разделитель внутри ячеек: `;`.

### Локализованные override

`requirementsOverride`, `benefitsOverride` и `requiredDocumentsOverride`
поддерживают **две формы**:

1. **Плоский массив строк** — одинаково для всех 12 языков (то, что в таблице
   выше).
2. **Объект `Partial<Record<SupportedLanguage, string[]>>`** — отдельный
   список на каждый язык. Используй, когда город требует юридически точной
   формулировки на не-русских языках.

```yaml
# 1. Плоский массив — одинаково для всех языков
requirementsOverride:
  - "Права категории B"
  - "Стаж вождения от 1 года"

# 2. Локализованный объект — на каждый язык свой список
requirementsOverride:
  ru:
    - "Права категории B"
    - "Стаж вождения от 1 года"
  uz:
    - "B toifa haydovchilik guvohnomasi"
    - "Kamida 1 yillik haydash tajribasi"
  uk:
    - "Права категорії B"
    - "Стаж водіння від 1 року"
```

Логика резолва (`resolveList` в `src/data/jobs.ts`): если язык не указан в
локализованном объекте — берётся `value.ru`. Если и `ru` нет — пустой
список. То есть достаточно заполнить `ru`, а остальные языки можно
добавлять точечно по мере необходимости.

## 9. Документы

Документы можно передавать на двух уровнях.

Базовые документы для всей вакансии:

```yaml
requiredDocuments:
  - "Паспорт"
  - "СНИЛС"
  - "ИНН"
  - "Реквизиты для выплат"
```

Дополнительные документы для конкретного offer:

```yaml
requiredDocumentsOverride:
  - "Водительское удостоверение категории B"
  - "СТС автомобиля"
```

Итоговая вакансия получит:

```text
requiredDocuments = content.requiredDocuments + offer.requiredDocumentsOverride
```

## 11. Как лучше присылать данные

Самый удобный формат:

1. Ссылка на Google Sheets с оплатой по городам и транспорту.
2. Ссылка или отдельная таблица с условиями найма по городам.
3. Текст описания вакансии в сообщении или отдельным файлом.
4. Реферальная ссылка для отклика.
5. Логотип или ссылка на логотип.
6. Список обязательных документов.
7. Комментарии по спорным местам: где зарплата примерная, где найм закрыт, где условия нужно уточнить.

Если данных не хватает, генератор может поставить безопасные значения:

| Нет данных | Значение по умолчанию |
| --- | --- |
| Возраст | `18` |
| Медкнижка | `unknown` |
| Валюта | `RUB` |
| Ссылка отклика | `#` |
| Точность зарплаты | `partner` |
| Активность offer | `true`, если явно не указано обратное |
| `transportProvision` | по транспорту: `foot`/`remote` → `not_required`, `bicycle`/`auto` → `own` |

## 12. Партнёрские ссылки и логотипы

Все `*_APPLY` URL и `*_LOGO` пути живут в **`src/data/partnerLinks.ts`** —
там же агрегатор `PARTNER_LINKS`. Для новой компании:

1. Добавь константы `<COMPANY>_APPLY` и `<COMPANY>_LOGO` в `partnerLinks.ts`.
2. Добавь запись в `PARTNER_LINKS` (для аудита через grep).
3. В `vacancies.ts` импортируй константы и используй их — НЕ вставляй URL
   литералом.

Зачем: один источник правды для ротации реферальных ссылок (`erid`,
`utm_*`) без поиска по всему репо.

## 13. Ozon — закрытая подсистема, не входит в этот формат

Этот документ описывает **только** добавление CPA-вакансий с реф-ссылкой
(стандартный флоу: клик → внешний редирект на лендинг партнёра). Ozon
сюда не относится — он уже добавлен и работает на отдельном механизме:

- 9 готовых ролей (5 sklad + 4 fresh) в `src/data/ozonOffers.ts`,
  генерируются из `src/data/ozon-vacancies.json` и
  `src/data/ozon-fresh-vacancies.json`.
- Магический префикс `applyLink: 'lead-form:ozon'` открывает встроенную
  `OzonLeadModal.astro` вместо редиректа.
- Модалка POST'ит лид в Cloudflare Worker `workers/ozon-lead/`, который
  валидирует тройку `(vacancy, cityID, hireObjectUUID)` и проксирует в
  `recruitment.ozon.ru`.

**Эту подсистему не расширяют в рамках «добавить новую вакансию».** Если
поступает CPA-партнёр с обычной реф-ссылкой — иди по основному флоу
(§§1–11). Если кто-то просит «как Ozon» (модалка, лид-форма) — это
отдельный, не-CPA сценарий, переспроси.
